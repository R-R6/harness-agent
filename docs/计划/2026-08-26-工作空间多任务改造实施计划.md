# 工作空间多任务改造实施计划

> [!info] 本文定位
> 交接文档的**可执行细化**。不重写需求，只把阶段拆到文件、测试缝、验证命令和明确不做。
> 阶段 3（Workspace.id 解耦 path）本轮不做。
> 审查结论：原稿阶段 2 看板回退会串台、焦点有一帧错配、引擎锁漏回滚；以下已按审查改过。

## 0. 本轮验收标准（按能力降级写死，避免按字面硬标准打回）

1. **同空间多任务（无头）**：同一工作空间可并发多个无头/模拟任务，列表按 `task_id` 独立看状态/取消。
2. **引擎同目录串行**：勾选「驱动 Claude 终端」时，同目录第二条应失败，文案为「该工作目录已有终端驱动任务在运行（同一 Claude 会话不能并行注入）」；第一条不受影响。这是预期，不是 bug。
3. **切空间 — 任务列表**：只显示激活空间的任务，count-pill 同步。
4. **切空间 — 审查看板**：显示该空间焦点任务的产物（见 D5）；请求的 `workDir` 为新空间 path。
5. **切空间 — 终端（折中，不是重建会话）**：Claude 目录输入框跟随新空间；若 Claude PTY 仍在旧目录则横幅提示，不杀/不重建 PTY。Codex pane 本轮不提示。

对照 Codex 两级模型：工作空间（一级）→ 任务（二级，从属于空间）。用户主用终端驱动，本轮硬标准 1 **只对无头完全满足**；引擎多 pane 化不在本轮。

## 1. 交接思路整理

```
用户两条硬标准
        │
        ├─ 问题 2：切空间串台 ── 实现缺陷，改动小 ── 阶段 1（先做）
        │     ├─ 1a 任务列表按激活空间过滤
        │     ├─ 1b 终端：不杀会话，只提示 Claude 归属不符
        │     └─ 1c 审查看板已按 path 加载，只回归
        │
        ├─ 问题 1：同空间不能再开任务 ── 原计划明确不做，用户已推翻 ── 阶段 2
        │     ├─ 无头（ps1）：进程可并发，但 .supervise/ 必须按 task_id 隔离
        │     └─ 引擎（终端驱动）：一个 Claude pane 同时只能喂一个任务 → 同目录串行
        │
        └─ 阶段 3 身份解耦 ── 长期可选，本轮不做
```

### 1.1 现状（代码已核对）

| 面 | 现状 | 文件 |
|----|------|------|
| 空间实体 | 有，path 为身份，`samePath` 去重 | `src/lib/workspaces.ts` |
| 任务注册表 | 有，`TaskInfo.id` + `work_dir` | `src-tauri/src/lib.rs` |
| 任务列表 | **传全局 `tasks`，未过滤** | `src/App.tsx` 692-694 |
| 同目录锁 | `busy_workdirs` 按 work_dir 互斥 | `lib.rs` `run_supervise` / `run_supervise_terminal` |
| 启动表单 | `runningTask` 单值，启动钮变成取消钮 | `SupervisePanel.tsx` |
| 审查看板 | 已按 `projectWorkDir` 加载 | `ReviewBoard.tsx` |
| 终端 | 单实例两 pane；切空间只改 Claude 目录输入框，PTY 不重建 | `TerminalWorkspace.tsx` |
| 状态栏 | `superviseRunning` 已是全局 running 条数 | `App.tsx` 116 |
| 会话浏览 | 不按 cwd 过滤（只按 agent） | `App.tsx` 432-435；本轮不改 |

跨空间并发**后端已经允许**（锁按目录，不同 path 不互斥）。用户感知的「不能多开」来自：同目录锁 + 前端表单单值阻塞。

### 1.2 交接文档低估的一点（必须写进阶段 2）

`.supervise/` **按工作目录共享**，不是按 task_id：

- 无头 `supervise.ps1` 的 `Reset-ArtifactDir` **启动时整目录删除** `.supervise`
- 引擎 `reset_artifacts` 删除根下 `review-*.md` 和 `final-report.json`（不递归、不删 `stop-markers.jsonl`）
- `ReviewBoard` 只读 `workDir/.supervise`
- `run_supervise` **先 spawn 再分配 task_id**，`spawn_supervise` 目前不设任何环境变量

只拆 `busy_workdirs`、允许同目录双无头任务，会互相清空产物，看板串台。阶段 2 必须做**按 task_id 隔离产物**，且 spawn 前分配 id。

## 2. 产品决策（本轮锁死）

| # | 决策 | 理由 |
|---|------|------|
| D1 | 阶段 1 先于阶段 2，各自独立可交付 | 问题 2 是缺陷；问题 1 是新能力且更大 |
| D2 | 终端隔离用**保守方案**：不杀 PTY，Claude 归属不符时横幅 | 交接首选；多 pane 化改动大 |
| D3 | 引擎任务：**同目录串行** | 一个 Claude pane 同时只能注入一个任务 |
| D4 | 无头任务：同目录允许并发，产物写 `.supervise/tasks/<task_id>/` | 满足「同空间再开」且不踩盘 |
| D5 | 看板跟随「焦点任务」：点列表选中；有效焦点在 **render 期派生** | 禁止 `useEffect` 回退造成一帧「新目录 + 旧任务」 |
| D6 | 表单始终可点「启动」（in-flight 期间 disable 防连点）；取消只走任务列表 | 取消已按 `task_id` |
| D7 | 表单日志只显示最近一次启动的 `taskId`；过滤用 ref；切 `workDir` 清空日志 | listener deps `[]`，不能闭包捕获 state |
| D8 | 阶段 3 不做 | 身份仍用 path + `samePath` |
| D9 | 本轮不改版本号 | 仍是 0.2.0 |
| D10 | 状态栏继续用**全局** running 计数 | 与列表 count-pill（当前空间）含义不同；切走后任务仍应在状态栏可见 |
| D11 | 会话浏览不按 cwd 过滤 | 硬标准未要求；禁止扩大范围 |
| D12 | 重启后任务注册表为空、磁盘 `tasks/<id>/` 看板看不见 | 与现有内存态一致，不做落盘 |

不做：Workspace.id 关联、任务落盘、每任务一 pane、删空间后任务「未分配」、无头脚本硬编码模型、会话 tab 按空间过滤、Codex pane 归属横幅、假的 Tauri 并发集成测试。

## 3. 阶段 1 — 空间彻底隔离

目标：切空间 = 任务列表和看板换成该空间；终端若 Claude 会话目录 ≠ 新空间则提示。

### 3.1 步骤 1a — 任务列表按空间过滤

**测试缝（先写失败用例）：**

1. `src/lib/__tests__/workspaces.test.ts`  
   `tasksForWorkspace(tasks, path)`：大小写/斜杠归一后只留下该 path；空 path → `[]`。
2. `src/__tests__/App.test.tsx`  
   - 两空间 **不同 basename**（`D:\space-alpha` / `D:\space-beta`），各一条任务。监督 tab 默认 A → 只见 A（用 `title={work_dir}` 或不同 basename），任务记录旁 count-pill = 1。切 B → 只见 B，A 消失。  
   - 另加「同 basename 不同 path」：`D:\projA\app` vs `D:\projB\app`，用 `li[title]` 断言不串台，禁止只靠可见文本 `app`。  
   - 切空间后 `read_review_artifacts` 用 `expect.objectContaining({ workDir: B路径 })`，不要精确匹配整个 payload（2b 会加 `taskId`）。

**实现（最小）：**

- `src/lib/workspaces.ts` 增加 `tasksForWorkspace`。
- `src/App.tsx`：`activeTasks = tasksForWorkspace(tasks, projectWorkDir)`，`TaskList` 和任务记录 count-pill 改用 `activeTasks`。状态栏 `superviseRunning` 仍用全局 `tasks`。
- `TaskList` 本身不改。

**验证：** `npx vitest run src/lib/__tests__/workspaces.test.ts src/__tests__/App.test.tsx` → 全绿；再 `npx tsc --noEmit`。

**提交：** `fix(workspaces): 任务列表按激活空间过滤，切空间不再串台`

### 3.2 步骤 1b — 终端归属提示

**测试缝：**

- `src/components/__tests__/TerminalWorkspace.test.tsx`  
  启动 Claude 后把 `projectWorkDir` 改成另一目录 → 出现提示，含旧/新 basename。  
  目录相同或不在 running → 无提示。  
  `invoke` 从未以 `stop_terminal` 被调用。  
  Codex pane 无此横幅。

**实现：**

- Claude pane：`running` 且 `session.work_dir` 与 `projectWorkDir` 的 `samePath` 为假 → 横幅：  
  「当前 Claude 终端对话属于「{旧 basename}」，与激活空间「{新 basename}」不同。停止后重新启动才会切到新空间。」
- 不强制停会话；目录输入框继续跟随 `projectWorkDir`。

**验证：** 该文件 vitest + `tsc --noEmit`。

**提交：** `fix(terminal): 切空间时提示 Claude 会话仍属于旧目录`

### 3.3 步骤 1c — 看板回归（无单独提交）

`ReviewBoard` 已按 `projectWorkDir` 加载。切空间断言写在 1a 的 App 测试里。

## 4. 阶段 2 — 同空间多任务

目标：同空间可再开无头任务并独立取消；引擎同目录仍互斥并给出明确错误。

### 4.1 步骤 2a — 后端锁 + 产物目录

**锁语义（替换 `busy_workdirs: Mutex<Vec<String>>`）：**

```
engine_busy_dirs: Mutex<HashSet<String>>  // 仅引擎：同目录互斥（pane）；键 = normalize_path 结果
tasks: HashMap<task_id, TaskInfo>         // 无头并发靠 task_id，不再按目录互斥
```

- `run_supervise`（ps1）：**删除**检查、登记、spawn 失败回滚、stdout.take 失败回滚、收尾 `busy_workdirs.retain` **全部四处**。不要改名后留幽灵 retain。
- `run_supervise_terminal`：同锁内若已含该目录 → 上述错误文案；否则插入。失败回滚清单必须三处都清 `engine_busy_dirs`：
  1. `create_dir_all`
  2. **`USERPROFILE`/`HOME` 解析**（现有 `?` 在登记之后，今天就不回滚，改锁后会永久锁死）
  3. `ensure_stop_hook`
- 收尾/取消：引擎结束时从 `engine_busy_dirs` 移除该目录；无头只动 `running` + `tasks`。取消只置 flag，锁仍由收尾线程清。
- `engine_dir_available(busy, dir)` 仅测「空集可、同目录不可、不同目录可」；锁键必须已是 `normalize_path` 结果。无头解锁靠代码审查（`run_supervise` 不再读写 `engine_busy_dirs`）+ 真机双无头，不写假的 Tauri 并发测试。

**产物隔离：**

| 模式 | 产物路径 | 启动清理 |
|------|----------|----------|
| 无头 | `{work_dir}/.supervise/tasks/{task_id}/` | 只删该子目录，然后**立刻重建空目录**。禁止 `Remove-Item .supervise -Recurse` |
| 引擎 | 仍 `{work_dir}/.supervise/` | 现有 `reset_artifacts`（只删根文件） |

无 `SUPERVISE_TASK_ID`：禁止回退整目录删除；报错退出，或只按文件删根上的 `review-*.md`/`final-report.json`（与引擎一致）。

`run_supervise`：**先** `task_id = task-{n}`，再 `spawn_supervise(&req, Some(&task_id))` 里 `cmd.env("SUPERVISE_TASK_ID", task_id)`。现有 spawn 测试传 `None`（签名做成可选）。

`read_artifacts(work_dir, task_id: Option<&str>)`：

- 无 `task_id` → 只读根 `.supervise/`（旧行为）。
- 有 `task_id` 且子目录 **存在**（含空）→ **只读子目录，禁止回退根**（刚启动无头、第一轮尚未落盘时看板应为空，不能串出引擎/旧产物）。
- 有 `task_id` 且子目录 **不存在** → 读根（引擎任务 + 旧产物）。

Tauri command `read_review_artifacts` 增加可选 `task_id`。

**Rust 测试（先红后绿）：**

1. `engine_dir_available`：空集可；同目录不可；不同目录可。
2. `read_artifacts`：根目录旧产物仍可读；子目录存在（含空）传入该 id 只读子目录、不回退根；传入别的 id 且该子目录不存在时才读根。
3. runner：有 task_id 时产物路径为 `.supervise/tasks/<id>`；`None` 时行为兼容。
4. 引擎 `reset_artifacts`：预置 `tasks/task-1/review-1.md` + `stop-markers.jsonl`，reset 后两者仍在。

**验证：**  
`cd src-tauri`，PATH 补 cargo bin，`CARGO_TARGET_DIR=target-check cargo test -p harness_agent -p supervise_runner -p supervise_engine`（用完删 `target-check`，勿提交）。

**提交：** `feat(supervise): 无头同目录可并发，引擎同目录仍互斥并按任务隔离产物`

### 4.2 步骤 2b — 前端表单 + 看板焦点 + 列表取消

**测试缝：**

1. `SupervisePanel.test.tsx`：启动成功后仍显示「启动监督闭环」，可再点第二次 invoke；无「取消任务」按钮。日志：task-1 出日志后再启动 task-2，只留 task-2。切 workDir 后日志清空。启动 in-flight 时按钮 disabled。
2. `App.test.tsx`：同空间两条 running；点第二条「取消」只 `cancel_supervise` 该 id。取消钮 `stopPropagation`，不把该行变成选中（若点取消会选中则加测）。
3. `ReviewBoard.test.tsx`：传入 `taskId` 时 invoke 带该参数；`taskId` 为 null/省略时 payload 不含 `taskId`（或与旧 `{ workDir }` 兼容）。

**实现：**

- `SupervisePanel`：去掉 `runningTask` 互斥与表单取消钮；`lastTaskId` 用 **ref** 过滤 log/done；`workDir` 变化清空 logs + lastTaskId；启动中 disable；删除 `onRunningChange` 的单任务 effect（App 已空接，props 可保留以免无关 diff，但 effect 必须删）。
- `App.tsx`：`focusedTaskId` 为用户点击；**有效焦点在 render 期派生**：若 `focusedTaskId` 不在 `activeTasks` 内，用该空间最新 running（`started_at_ms` 大者优先，与 `list_supervise_tasks` 最新在前一致），否则最新一条，再否则 `null`。传给 `ReviewBoard`。
- `TaskList`：行可点击选中（`aria-selected`）；取消钮 `stopPropagation`。
- `api.ts` `fetchReviewArtifacts(workDir, taskId?)`；`null` 时 invoke 不带 `taskId`。
- `ReviewBoard`：`taskId` 进 `load` 的 deps。

**验证：** `npm test` + `npx tsc --noEmit`。

**提交：** `feat(supervise): 同空间可再开任务，看板跟随选中任务`

### 4.3 真机验证看点（交给用户）

阶段 1：两个空间，A 有一条历史任务，切 B 列表空、看板请求换目录、终端若 Claude 仍在 A 则出现横幅（仅 Claude，Codex 不提示）。状态栏若其它空间仍有 running，数字不会因切走而清零。

阶段 2：同一空间连续开两个**无头/模拟**任务，列表两条 running，可分别取消；看板点哪条看哪条；刚启动尚未落盘时看板为空（不串旧产物）。勾选「驱动 Claude 终端」开第二个应失败且第一条不受影响。

## 5. 执行顺序与停条件

```
1a 测试红 → 实现 → 绿 → commit
1b 测试红 → 实现 → 绿 → commit
2a 测试红 → 实现 → 绿 → commit
2b 测试红 → 实现 → 绿 → commit
停止。不开始阶段 3。不发版。不 push。
```

每步失败：保持未验证实验，不靠顺手改无关代码把测试刷绿。

## 6. 协作与环境（沿用交接，不重复）

- 中文 Conventional Commits；禁止 AI 署名尾注。
- 本轮**只 commit、不 push**（当前对话未要求 push；交接里的 push 惯例本轮不跟）。
- cargo 不在默认 PATH；编译检查用 `CARGO_TARGET_DIR=target-check`；`target-check` 绝不入库。
- 不改 `package.json` / `Cargo.toml` 版本。

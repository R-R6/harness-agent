# 监督闭环任务隔离与持久化实施计划

> [!info] 本文定位
> 修「监督闭环」的任务级隔离、跨空间状态保留、任务记录持久化三个方向。不重写需求，只拆到文件、数据模型、验证命令。
> 四个问题 + 三个决策点（D1/D2/D3）均已被用户确认，见文末「已锁定决策」。

## 0. 需求清单（R1–R8）

| 编号 | 需求 | 来源 |
|------|------|------|
| R1 | 切换任务记录 → 显示该任务的**描述** | 问题 1 |
| R2 | 描述 + 监督日志**按任务隔离**；工作目录跟随空间（不隔离） | 问题 2 |
| R3 | 工作空间隔离（已工作，**不改**） | 问题 3 |
| R4 | 切空间/切任务**不丢界面进度**：日志保留、焦点按空间记忆、状态不漂移 | 问题 4 |
| R5 | 任务记录**文件系统持久化**（重启保留），未删除的长期保留 | 新需求 |
| R6 | 用户可**删除**任务记录（后端命令 + UI 按钮） | 新需求 |
| R7 | 焦点按空间记忆，首次进入默认聚焦最新任务 | 已确认 |
| R8 | 选中任务 → 描述**只读**显示；另有「新建任务」入口回到可编辑表单 | UX |

## 1. 现状与根因（浓缩）

- **描述没存**：后端 `TaskInfo`（`lib.rs` 41–51）没有 `task` 字段；`run_supervise`（448）/`run_supervise_terminal`（679）登记时丢弃 `request.task`；前端 `SupervisePanel` 的「任务描述」是本地 `task` state，跟选中任务无关 → 问题 1。
- **日志没隔离**：`SupervisePanel` 用 `logs` + `lastTaskIdRef` 只留「最后启动任务」的日志（监听器 47 行 `if taskId !== lastTaskIdRef return`）；`useEffect([workDir])`（70–74）切空间清日志；`start()` 里 `setLogs([])`（102）清上一个任务日志 → 问题 2/4。
- **焦点漂移**：`App.tsx` 118–124 `focusedTaskIdEffective` 是「自动选最新 running」的派生回退，任务跑完/切空间时焦点漂到别处 → 问题 4 的「任务状态被改变」。
- **无持久化**：`SuperviseState.tasks` 是内存 `HashMap`，重启即空；无删除命令/UI → 新需求。

## 2. 数据模型

**后端 `TaskInfo`**（加 `task` + `log`，补 `Deserialize`）：

```rust
#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]
struct TaskInfo {
    id: String,
    work_dir: String,
    task: String,        // 新增：任务描述
    kind: TaskKind,
    status: TaskStatus,
    rounds: i64,
    last_reason: String,
    log: Vec<String>,    // 新增：监督日志（限 500 行）
    started_at_ms: u64,
}
```

**前端 `TaskInfo`**（`types.ts`）：加 `task: string; log: string[];`。

## 3. 后端改造（`src-tauri/src/lib.rs` 为主）

1. `TaskInfo` 加字段 + `Deserialize`；登记时写入 `request.task`。
2. **日志收集**：ps1 stdout/stderr 线程（466/499）与引擎 `on_log`（728）在 `emit("supervise-log")` 的同时，`state.tasks.lock()` 往 `TaskInfo.log` 追加（截断到 500 行）。
3. **持久化**：
   - 文件：`{app_data_dir}/supervise/tasks.json`（`app.path().app_data_dir()`，本机 `%APPDATA%\com.mgzxtech.harness-agent\`）。
   - 加载：`setup`（890）读文件填充 `state.tasks`；启动时把 `status == Running` 标 `Aborted`（重启后无进程在跑）。
   - 保存：任务启动 / 终态 / 删除 / 关窗（`CloseRequested` 925）时写盘（临时文件 + rename 原子写）。
4. **删除命令** `delete_supervise_task(task_id)`：从 `tasks` 移除 + 落盘；运行中拒绝（提示先取消）；连带删 `.supervise/tasks/<task_id>/` 产物。
5. 注册命令 + 更新 `task_info_serializes_to_snake_case` 测试 + 补序列化 round-trip 测试。

## 4. 前端改造

1. `types.ts` 加字段；`api.ts` 加 `deleteTask(taskId)` → `invoke("delete_supervise_task")`。
2. **焦点按空间**（`App.tsx`）：`focusByWorkspace: Record<workspaceId, taskId>`；`focusedTaskId` 从激活空间查表；点选/启动写入当前空间表；去掉「自动选最新 running」漂移，首次进入某空间默认最新任务（R7）。
3. **日志显示**：`tasks` 已含 `log`；`supervise-log` 事件实时 append 到对应任务 `log`；`SupervisePanel` 展示焦点任务日志，**去掉两处清空**（`useEffect([workDir])` + `start()` 的 `setLogs([])`）。
4. **SupervisePanel 双模式**（R8）：有焦点任务 → 查看态（描述只读 + 日志只读）；无焦点任务 → 编辑态（表单启动）；顶部「新建任务」入口清空焦点。
5. **TaskList 删除按钮**（R6）：非 running 任务行加「删除」+ 确认；调用 `deleteTask` 后刷新列表。

## 5. 持久化设计

| 项 | 方案 |
|---|---|
| 位置 | 全局 `app_data_dir()/supervise/tasks.json`（对照 Codex `~/.codex`、Claude `~/.claude`，均全局不写项目） |
| 格式 | `TaskInfo[]` JSON（含 task/log） |
| 写盘时机 | 启动 / 终态 / 删除 / 关窗；日志逐行只进内存、终态落盘 |
| 重启后 running | 统一标 `aborted` |
| 日志上限 | 每任务 500 行 |

## 6. 删除逻辑

- 后端 `delete_supervise_task`（见 §3.4）。
- 前端 TaskList 行尾「删除」（仅终态任务）→ `confirm` → 删除 + 刷新 + 若删焦点任务则清焦点。

## 7. 已锁定决策

| 决策 | 结论 |
|------|------|
| D1 日志是否持久化 | 是（每任务 500 行封顶） |
| D2 删除连带删产物 | 是（`.supervise/tasks/<id>/`） |
| D3 位置 | 全局 `app_data_dir()/supervise/tasks.json`；产物仍留项目 `.supervise/` |

## 8. 实施顺序 + 验证

1. 后端：TaskInfo 字段 + 登记写描述 + 日志收集 → `cargo check`。
2. 后端：持久化 load/save + 启动标 aborted + `delete_supervise_task` → 更新/补 Rust 测试 → `cargo test`。
3. 前端：types/api → 焦点按空间 → SupervisePanel 双模式 + 日志显示 → TaskList 删除 → `tsc` + vitest。
4. 全量：vitest + tsc + cargo test/check。
5. 真机验收：同目录双任务、切空间往返日志/焦点不丢、重启后任务仍在、删除生效。

## 9. 风险与边界

- 日志只在本会话内实时追加、终态落盘；运行中崩溃则该任务下次标 `aborted`、未落盘的部分日志丢失（可接受）。
- `tasks.json` 单文件随任务数增长；量大了再按 Codex 拆 `index.json` + `logs/<id>.jsonl`。
- 不改变产物 `.supervise/tasks/<id>/` 的项目内位置（R5 语义不变）。

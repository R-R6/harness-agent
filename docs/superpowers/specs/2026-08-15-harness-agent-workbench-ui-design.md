# Harness Agent 开发者工作台 UI 架构升级设计

日期：2026-08-15  
状态：已实现，待运行时桌面验收（含终端工作台扩展）  
范围：Tauri + React 桌面端 UI 架构、视觉系统、交互入口与应用图标

## 1. 目标与设计基线

Harness Agent 是一个面向开发者的桌面工作台，核心链路是：浏览 Claude/Codex 会话、启动监督闭环、检查 agent-sessions MCP 健康状态。本次升级参考 Claude Code 与 Codex 桌面端的工作台特征：低干扰的深色表面、明确的工作区边界、可扫描的状态信息、保留上下文的多栏布局和键盘优先操作。

采用“开发者工作台”方案：保留现有三大能力与数据流，重做应用壳层、信息层级、视觉 token、反馈状态和图标表达。深色主题默认，浅色主题可切换；两套主题共享相同语义 token。

## 2. 不变的功能边界

以下能力必须保留，除非后续另行获得明确授权：

- 会话搜索、数量限制、刷新、Claude/Codex 双栏列表、列表独立滚动和可拖拽分隔线。
- 会话收藏置顶、右键菜单、复制文件路径、复制会话 ID、复制续聊命令、在文件夹中显示、导出 Markdown。
- 选中会话后的正文加载、正文缓存、消息类型与时间显示。
- 监督闭环的任务描述、工作目录选择、L0/L1/L2 分级、模拟模式、启动/取消、实时日志和 500 行日志上限。
- 审查看板的轮次、PASS/REVIEW、理由、模型和会话 ID。
- MCP 检查、重新检查、一键修复、修复结果和备份路径。
- 现有 Tauri command、MCP 接口、前端 API 契约和 `supervise-log` / `supervise-done` 事件名。

页面切换继续使用常驻组件策略，切换工作区不清空已加载的会话、正文、日志或审查状态。

## 3. 明确新增的 UI 能力

这些是本次升级允许新增的展示或操作入口，不改变后端业务契约：

1. 深色/浅色主题切换，记忆用户选择。
2. 会话来源筛选（全部、Claude、Codex），作为现有双栏列表的视图入口。
3. 会话列表键盘上下选择、回车打开、Esc 清除搜索，以及可见焦点状态。
4. 固定底部状态栏，显示当前工作区、任务状态、MCP 连接状态和快捷键提示。
5. 阅读器标题区保留 Agent、更新时间和文件路径；复制、打开所在目录等操作继续通过现有右键菜单提供。
6. 统一的代码内置 SVG 图标组件，替换结构性 emoji 图标。
7. 使用自有无文字几何 H 标记，采用 Claude 暖橙/Codex 电蓝双色轨道，并导出 Windows/Tauri 所需的多尺寸资产。

来源筛选、键盘导航和阅读器快捷入口均属于现有能力的可见入口，不得引入新的数据源或改变搜索结果语义。

## 4. 应用壳层与组件边界

### 4.1 AppShell

`AppShell` 负责主题上下文、全局快捷键、页面级错误提示和工作区布局。继续使用原生 Tauri 窗口框架，不自定义标题栏，以避免窗口拖动、系统按钮和高 DPI 兼容问题。

### 4.2 WorkspaceNav

窄型图标导航默认显示图标和当前项选中线；可展开为文字导航。包含会话浏览、终端工作台、监督闭环、MCP 状态四个入口，并在底部展示真实 MCP 健康状态、Claude/Codex 数量和主题入口。`Ctrl/Cmd + 1/2/3/4` 保持可用，输入控件聚焦时不切换工作区。

### 4.3 WorkspaceView

只负责当前工作区的显示与布局，不拥有后端数据请求。现有 `SessionList`、`TranscriptView`、`SupervisePanel`、`ReviewBoard`、`MCPStatusPanel` 继续作为领域组件，通过更清晰的容器组件组合。

### 4.4 Feedback 与基础组件

新增共享的 `FeedbackBanner`、`EmptyState`、`Skeleton`、`IconButton`、`StatusBadge`、`ThemeToggle` 和 SVG 图标映射。所有异步页面统一呈现 loading、success、error 三态；错误信息靠近触发区域，同时保留页面级摘要。

## 5. 视觉系统

### 5.1 颜色

深色默认 token：

- `--bg: #0E1116`
- `--panel: #151A21`
- `--surface: #1C232D`
- `--hover: #222B36`
- `--border: #2A3441`
- `--text: #F2F4F7`
- `--text-secondary: #AAB4C2`
- `--text-muted: #7C8796`

浅色 token 映射到 `#F4F6F8 / #FFFFFF / #E9EDF2` 等相同层级。Claude 使用暖橙 `#D97757`，Codex 使用电蓝 `#5B8CFF`。成功、警告、失败状态必须同时使用文字或图标，不以颜色作为唯一信息。

### 5.2 排版、间距与形状

- Segoe UI / Microsoft YaHei 为界面字体；正文 13–14px，标题 16–18px，辅助信息不低于 12px。
- JSONL、路径和日志使用等宽字体；长文本行高约 1.55，并限制阅读宽度。
- 使用 4/8px 间距节奏；普通卡片圆角 8px，浮层 10px。
- 主按钮高度至少 36px，图标按钮命中区至少 40×40px；提供 tooltip、键盘焦点和 `aria-label`。

### 5.3 动效与可访问性

微交互时长 150–250ms，过渡不改变布局尺寸；支持 `prefers-reduced-motion`。分隔线拖拽提供 hover/focus 反馈和可读的 ARIA 值。颜色对比度以普通文本至少 4.5:1 为目标，焦点环不能被移除。

## 6. 页面级体验

### 6.1 会话浏览

顶栏包含工作区标题、来源筛选、搜索和刷新；数量限制和主题切换进入视图设置。双栏列表保留 Claude/Codex 分组、数量、收藏、时间和独立滚动；方向键、Home/End 和 Esc 支持键盘浏览。选中项使用身份色细线加低对比背景。正文阅读器标题区显示 Agent、更新时间和文件路径；正文按消息角色分块。无选中项时显示工作台式空态与快捷键提示。

### 6.2 监督闭环

采用“配置 → 实时日志 → 审查看板”的三列流程。配置区突出任务描述，工作目录、审查级别和模拟模式作为次级设置，启动/取消固定在区块底部。日志区保留终端语义但不使用纯黑大块，按 STEP/PASS/WARN/ERROR 展示标签与状态色。审查看板以轮次时间线显示 verdict、理由、模型和 session ID。

### 6.3 MCP 状态

顶部总览卡显示健康状态、检查项数量、最近检查时间和配置文件路径。检查项卡片明确显示注册、依赖和真实握手状态及详情。“重新检查”为次级动作；仅在异常时显示“一键修复”主动作。修复结果显示备份路径并支持复制。

## 7. 图标与资产策略

结构性界面图标使用统一笔画、尺寸和语义的内置 SVG，不使用 emoji。应用图标以 `src/assets/harness-mark.svg` 为透明背景的无文字几何 H 标记，再由 Tauri 图标生成器导出多尺寸 `src-tauri/icons` 及 `index.html` favicon。当前会话没有可调用的 ImageGen 工具，因此没有把 SVG 标记误报为 AI 生成位图；后续可在 ImageGen 可用时基于相同品牌方向探索替代版本。

## 8. 非功能与验收标准

- 在 1024×700 最小窗口和 1280×800 默认窗口验证，不产生水平滚动。
- 深色、浅色主题均通过可读性和焦点状态检查。
- 键盘可访问导航、搜索、会话选择、分隔线和所有主要按钮。
- 异步操作均可见地反馈进行中、成功和失败，已有内容不因刷新闪白。
- 会话正文缓存、监督日志上限、任务取消、MCP 修复后二次检查行为不回归。
- `npm run build` 与现有测试通过；必要时为新增主题、来源筛选、键盘导航和反馈状态补充组件测试。
- Tauri 图标在 Windows 高 DPI 下无明显模糊或透明边缘脏点。

## 9. 实施顺序（设计层）

1. 建立主题 token、基础 SVG 图标、反馈组件和 AppShell。
2. 重构三块工作区的容器与布局，保持现有领域组件和 API 调用。
3. 接入主题切换、来源筛选、键盘导航和阅读器快捷入口。
4. 生成、检查并接入应用图标多尺寸资产。
5. 运行构建、测试和桌面尺寸/主题/键盘验收。

本设计不包含后端重构、数据格式迁移、命令语义改变或删除现有功能。

## 10. 终端工作台扩展

### 10.1 目标与范围

终端工作台是第四个工作区，用于在 Harness Agent 内查看和操作用户本机已经安装、已经登录的 Claude Code 与 Codex CLI。这里的“终端界面”指交互式终端流，不是物理 COM 串口；它不修改两个 CLI 的源码，不打包或替换 CLI，不代理模型请求，也不读取或接管用户凭据。

### 10.2 运行模型

每个 Agent 维护一个独立的 PTY/ConPTY 子进程：

```text
Harness Agent
├─ Claude terminal session → PTY/ConPTY → claude CLI
└─ Codex terminal session   → PTY/ConPTY → codex CLI
```

Rust 侧负责 PTY 创建、字节流读取、输入写入、终端尺寸同步、退出码和进程树清理；React 侧使用终端模拟器渲染 ANSI、光标、颜色、滚动缓冲和键盘输入。现有监督任务的普通 stdout/stderr 管道继续保留，不能与交互式 PTY 混用。

每个终端都有独立的 `terminalSessionId`、Agent、工作目录、状态（未启动/启动中/运行中/停止中/已退出/错误）和退出原因；它与现有 JSONL 会话 ID 分离。终端输出默认只保存在当前内存缓冲中，不再复制落盘，以降低 API key、环境变量和项目机密泄露风险。

### 10.3 工作区布局与操作

- 左侧继续使用统一的 WorkspaceNav，新增“终端工作台”入口；现有三个工作区不改变默认行为。
- 中央显示 Claude 与 Codex 两个固定 pane；窗口窄于可读宽度时垂直排列，避免压缩终端字符列。
- 每个 pane 顶部显示 Agent 标识、运行状态、当前工作目录，以及启动、停止和清屏操作。
- 默认按需启动，进入工作区不会自动拉起 CLI；切换到其他工作区时终端进程、滚动缓冲和当前输入状态保持不变。
- 会话列表的“复制续聊命令”可以新增“在对应终端恢复”入口，继续使用现有 `claude --resume <id>` / `codex resume <id>` 语义。
- 工作目录由每个 pane 显式输入；CLI 默认通过用户 PATH 中的 `claude` / `codex` 解析，不会下载、捆绑或静默替换可执行文件。

### 10.4 新增能力与不变能力

新增：终端工作区、两个 PTY pane、按需启动/停止/清屏、工作目录选择和终端状态显示。  
保留：会话浏览、JSONL 阅读、监督闭环、MCP 检查/修复、现有 Tauri command、现有监督事件和数据格式。终端工作区不会替代会话阅读器，也不会改变监督闭环的进程管理。

### 10.5 生命周期与安全边界

- 使用用户明确配置的本机 CLI；不捆绑 Claude Code/Codex 二进制，不自动下载安装。
- 不保存、不显示、不上传 token；终端输出不写入 Harness Agent 自己的日志文件。
- 启动前明确显示 CLI 路径和工作目录；工作目录不存在或 CLI 不可执行时，在 pane 内给出可恢复的错误。
- 应用退出或停止时可靠清理 PTY 及其子进程树；当前实现使用 ConPTY/portable-pty 加 Windows `taskkill /T /F`，不能只依赖前端卸载。
- 终端输入支持 Ctrl+C、Ctrl+D、Esc、上下键、Tab、粘贴和中文输入；窗口 resize 必须同步到 PTY，避免全屏 CLI 布局错位。

### 10.6 合规姿态

Harness Agent 仅作为本机 CLI 的第三方工作台，不宣称 Anthropic 或 OpenAI 官方背书。界面使用 Harness Agent 自有图标与品牌；Claude Code、Codex 仅作为集成目标名称。不得逆向隐藏协议、拦截模型请求、绕过登录/额度/风控、收集凭据或在安装包中再分发未获授权的 CLI。若将软件公开发行或商业销售，需依据实际版本、地区和订阅计划核对两个产品的最新许可与服务条款，并在 About/Integrations 页面提供第三方集成声明。

### 10.7 终端验收

- 两个 pane 可以同时运行、输入和退出，互不吞键、不串输出。
- Claude/Codex 的颜色、光标、确认提示、流式输出和窗口 resize 在 1024×700 与 1280×800 下可用。
- 切换工作区不终止进程；停止、应用退出和异常退出都能回收子进程。
- 未安装 CLI、未登录、工作目录无效、CLI 崩溃时均显示可理解的错误与重试入口。
- 终端功能不影响现有会话、监督闭环和 MCP 测试；构建、组件测试和 Rust 测试通过。

## 1. 产品需求（已锁死，勿再议范围）

对照 Codex：**工作空间（一级）→ 任务（二级，从属于空间）**。

| # | 需求 | 验收口径 |
|---|------|----------|
| R1 | **同空间多任务** | 同一工作空间可开多条监督任务；列表按 `task_id` 独立看状态、独立取消 |
| R2 | **切空间不串台** | 切工作空间后：任务列表、审查看板、终端**上下文**换成该空间；不把别的空间任务/看板混进来 |
| R3 | **保留驱动 Claude 终端 + 人可插手** | 「驱动 Claude 终端」路径必须继续可用；人能在 PTY 里介入 |
| R4 | **真并发 = 一任务一 Claude PTY** | 引擎路径：**同目录允许多个 Claude 进程**；**不设进程数硬上限**（压测用）；**同一 PTY** 上再注入则失败（「该 Claude 终端已有监督任务在运行」） |
| R5 | **产物按任务隔离** | 引擎/无头产物写 `.supervise/tasks/<task_id>/`；无选中任务时看板不读盘 |

**本轮明确不做（仍有效）：**

- Workspace.id 与 path 解耦（阶段 3）
- 任务注册表跨应用重启持久化
- 进程数硬上限
- 会话浏览按 cwd 过滤
- Codex pane 目录归属横幅
- 改版本号（仍 0.2.0）

产品覆写记录：计划里原 D3「引擎同目录串行」已被用户改为 R4 多进程（见 `docs/计划/2026-08-26-工作空间多任务改造实施计划.md` 文首说明）。

## 4. 已落地能力说明（可对照代码）

### 4.1 工作空间隔离（阶段 1）

- 侧栏工作空间：`path` 为身份，`samePath` 去重（`src/lib/workspaces.ts`）。
- 任务列表 / count-pill：只展示当前 `projectWorkDir` 下任务。
- 审查看板：`workDir` + `taskId`；切空间后有效焦点在 render 期重算，避免「新目录 + 旧 taskId」一帧串台。
- 终端：切空间更新 Claude 目录输入；若 PTY 仍属旧目录 → 提示，**不杀 PTY**。
- 状态栏 `superviseRunning`：仍为**全局** running 条数（与当前空间 count-pill 含义不同，属 D10）。

### 4.2 同空间多任务 — 无头

- 同目录可并发多条无头/模拟任务。
- 产物目录：`.supervise/tasks/<task_id>/`。
- Stop markers 等共享根目录文件的行为：以 runner/engine 源码为准；引擎侧用 `task_token` 预钉，避免多进程抢同一 Stop 流。

### 4.3 同空间多任务 — 引擎（后端，tip 已具备）

关键路径（`src-tauri/src/lib.rs` → `supervise_engine`）：

1. 请求可带 `terminal_session_id`（类型在 `SuperviseRequest` / TS `types`）。
2. `engine_busy_sessions`：按 Claude PTY session id 互斥，**不再**用整目录 `busy_workdirs` 挡同目录第二任务。
3. 未传 session 时：尝试绑定该目录下**空闲** Claude；没有则错误提示先启动 Claude。
4. 注入 token `[supervise-task:<id>]`，精确匹配（避免 `task-1` / `task-10` 子串误伤）。
5. 钉 session 失败则失败关闭（评审后修过）。
6. `engine_hook_refs`：多引擎共享 Stop hook 安装计数，避免 mock/多任务误卸 hook。

### 4.4 前端驱动接线（设计已有，工作区未接）

`SupervisePanel`：

```ts
prepareDriveTerminal?: (workDir: string) => Promise<string>;
// drive 时：terminal_session_id: await prepareDriveTerminal(dir)
```

`d28a661` 中 `App` 曾：`prepareDriveTerminal` → `terminalRef.startClaudeForTask(workDir)`。

**当前 `App` 未传该 prop** → 勾选驱动时**不会**自动开新 Claude；只会在已有空闲 session 时由后端绑定。

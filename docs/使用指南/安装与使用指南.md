# Harness Agent —— 安装与使用指南（Windows / macOS）

> 首版 Windows 内部版（已支持 macOS）。桌面端：会话浏览器（Claude/Codex 分组 + 全文搜索）
> + 监督闭环（Claude 干活 → Codex 审查 → 返工）+ MCP 健康检查。

## 一、安装（首次装）

**执行目录**：装完从开始菜单/桌面双击打开，不需要命令行。

1. 安装包位置：`F:\project\workspace-side\Harness_agent\src-tauri\target\release\bundle\nsis\`
   - 文件名形如：`Harness Agent_0.1.0_x64-setup.exe`
2. 双击安装包 → 一路「下一步」→ 完成
3. 打开应用：开始菜单搜 **Harness Agent**（或桌面快捷方式）

### ⚠️ 首次运行遇到「Windows 已保护你的电脑」

因为安装包**没有代码签名证书**（内部版没买证书），SmartScreen 会拦截：

```
Windows 已保护你的电脑
Microsoft Defender SmartScreen 已阻止启动一个未识别的应用
```

**处理步骤**（3 步）：
1. 点击 **「更多信息」**（在提示文字下方的小字链接）
2. 出现 **「仍要运行」** 按钮 → 点击
3. 应用启动，安装完成

> 说明：这是自签名/未签名应用的正常提示，不是病毒。
> 自己电脑上信任后，以后安装不再提示。

### 1. 会话浏览
- 左侧列表按 **Claude Code（橙）/ Codex（蓝）** 分组，显示会话标题 + 北京时间
- 顶部搜索框：按关键词搜**对话内容**（排除工具输出杂音），结果上方有「✕ 清除」
- 点会话看正文；右侧分割线可拖动调宽度

### 2. 监督闭环（核心功能）

> v0.2 起支持**多工作空间**（Codex 同款两级模型）：左侧空间栏管理项目目录，
> 右侧是该空间的 [任务记录 + 启动表单 + 审查看板]。

1. **添加工作空间**：监督页左侧点「+」→ 选项目目录 → **信任确认**（说明该目录
   将被注入任务/写审查产物）→ 加入列表并激活
2. 激活空间（左侧高亮）后填**任务描述**（如"写一个猜数字游戏，要带输入校验"）
3. 选**分级**（L0 最快 / L1 默认 / L2 最严）+ 勾选**模拟模式**（不花钱跑流程）
   + 可选**驱动 Claude 终端**（注入运行中的终端 pane，干活全程可见）
4. 点「启动监督闭环」→ 右侧任务列表出现运行中记录，下方实时日志流，
   审查看板显示逐轮审查卡片
5. 闭环：**Claude 干活 → Codex 读真实会话审查 → 意见回灌 → 返工**，最多按分级轮数
6. 空间管理：点名称可**重命名**（双击），点「✕」移除；切换空间 = 切换任务上下文

> 真实模式需要本机已配置 `claude` / `codex` 命令行工具。
> 产物落在 `工作目录\.supervise\`（review-N.md + final-report.json）。
> 任务记录存于内存注册表（应用重启后清空，属预期）。

### 3. MCP 状态
- 检查 agent-sessions MCP 注册（Codex 桌面端重写 config.toml 会冲掉注册）
- 发现异常 → 点「一键修复」（自动备份 + 补注册段 + 原子写）
- 含真实握手验证（spawn node server.js 发 initialize）

## 三、常见问题

| 问题 | 解决 |
|---|---|
| SmartScreen 拦截 | 见上文「更多信息 → 仍要运行」 |
| 会话列表是空的 | 确认本机跑过 Claude Code / Codex（有 .claude/.codex 会话目录） |
| MCP 状态显示异常 | 点「一键修复」，改完**新开** Codex 会话生效 |
| 监督闭环卡住 | 点「取消」；真实模式首次跑较慢（Claude 干活 + Codex 审查） |

## 五、macOS 版

### 安装（首次装）

1. 安装包位置：`src-tauri/target/release/bundle/`（`dmg/Harness Agent_0.1.0_aarch64.dmg` 或 `macos/Harness Agent.app`）
2. 双击 .dmg → 把 **Harness Agent** 拖进「应用程序」（或直接用 bundle 里的 .app）
3. 从启动台 / Applications 打开

### ⚠️ 首次打开「无法打开，因为无法验证开发者」

安装包**没有 Apple 开发者签名/公证**（内部版），Gatekeeper 会拦截：

```
"Harness Agent" cannot be opened because the developer cannot be verified.
```

**处理步骤**（任选其一）：
- **右键点击** .app → **打开** → 弹窗里再点「打开」（推荐，一次放行）
- 或：系统设置 → 隐私与安全性 → 底部「仍要打开」

> 说明：未签名自建应用的正常提示，不是病毒。

### 运行前提（CLI 工具链）

监督闭环与终端工作台依赖本机的 `claude` / `codex` CLI 与 `pwsh`：

```bash
# PowerShell（监督引擎运行时）
brew install powershell

# 两个 CLI（装完各自登录一次）
npm install -g @anthropic-ai/claude-code
npm install -g @openai/codex
```

> GUI 应用启动时会自动采集登录 shell 的 PATH（含 Homebrew / npm 全局 bin），
> Finder/Dock 直接打开也能找到上述命令，无需额外配置。

### 与 Windows 版的已知差异

| 差异点 | 说明 |
|---|---|
| 无 GBK 编码问题 | macOS 终端/管道原生 UTF-8，中文日志与产物不会乱码 |
| MCP 宿主文件名 | `codex-code-mode-host`（无 `.exe` 后缀），健康检查已按平台识别 |
| 模拟模式（-Mock） | 仅开发模式（`npm run tauri dev`）可用；打包版 .app 内资源目录只读（且可能被 Gatekeeper 转置），Mock 数据无处落盘 |
| 路径大小写 | 大小写敏感 APFS 卷上，两个仅大小写不同的工作目录会被判为同一目录（保守误拒，不影响数据） |

### 开发（macOS）

```bash
# 开发模式（热更新）
npm install
npm run tauri dev

# 重新打包（产出未签名 .app + .dmg）
npm run tauri build

# 测试
npm test && cd src-tauri && cargo test --workspace
```

> 依赖：Xcode 命令行工具（`xcode-select --install`）+ Rust stable（rustup）+ Node ≥ 20。
> macOS 构建产出当前架构包（Apple Silicon 为 aarch64）；universal 包需显式
> `npm run tauri build -- --target universal-apple-darwin`。

**DMG 打包失败的兜底**：`tauri build` 的 DMG 步骤依赖 Finder AppleScript 做装饰性
窗口布局，未授权「自动化→Finder」时会报 `AppleEvent 已超时 (-1712)`（.app 不受影
响，已正常产出）。两种解决方式任选：
- 系统设置 → 隐私与安全性 → 自动化 → 给终端工具勾选 Finder，重跑 `npm run tauri build`
- 直接用兜底脚本出标准 DMG（无装饰布局，内容一致）：`bash scripts/build-macos-dmg.sh`
